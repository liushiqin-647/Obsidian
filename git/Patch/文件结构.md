# Patch 文件详解

## 概述

一个 `patch`文件（也称为补丁文件）通常用于记录源代码或其他文本文件的差异，以便将其应用于另一个副本。它遵循一个**标准格式**，最常用的是由 `diff`工具生成的“统一差异”（unified diff）格式。下面是其核心结构、示例及特定格式的扩展说明。

## 一、核心结构

### 1. 文件头（Header）

包含补丁的整体信息，通常至少有两行：
- **第一行**：指明源文件和目标文件。格式如下：
```
--- a/path/to/original_file
+++ b/path/to/modified_file
```
- `---`表示原始文件（旧版本）。
- `+++`表示修改后的文件（新版本）。
- 路径前的 `a/`和 `b/`通常代表两个不同的目录（如版本库中的旧版和新版），有时会被省略。
- **可选的上下文信息**：例如 `@@ -R +R @@`行之前的元数据，如：
```
diff --git a/file.txt b/file.txt
index 789abcd..1234567 100644
```
- 这是 Git 等版本控制系统生成的额外信息。

### 2. 变更块（Hunk）

一个 patch 文件可能包含多个变更块（每个块对应文件中一个连续的修改区域）。每个块的结构如下：
- **块头**：
```
@@ -L,S +L,S @@ [可选的上下文描述]
```
- `-L,S`：原始文件中此块的位置。`L`是起始行号，`S`是块的行数（默认为上下文行数）。
- `+L,S`：新文件中此块的位置。
- 例如 `@@ -10,6 +10,8 @@`表示：原始文件从第10行开始的6行内容，对应新文件从第10行开始的8行内容。
- **块内容**：由以下符号开头的行组成：
- **空格**：未更改的行（上下文行）。
- **`-`**：仅在原始文件中存在的行（被删除）。
- **`+`**：仅在新文件中存在的行（被添加）。

### 3. 多个文件的补丁

一个 patch 文件可以包含多个文件的修改。每个文件以新的文件头开始，例如：
```
--- a/file1.txt
+++ b/file1.txt
@@ ... @@
...（变更内容）
--- a/file2.txt
+++ b/file2.txt
@@ ... @@
...（变更内容）
```
## 二、标准格式示例
```
diff
--- a/hello.txt
+++ b/hello.txt
@@ -1,3 +1,4 @@
Hello world!
-This is old text.
+This is new text.
And here is another line.
+Added a new line here.
```
**解释**：
- 原始文件 `hello.txt`的第1到3行被修改。
- 删除了一行（`-This is old text.`）。
- 添加了两行（`+This is new text.`和 `+Added a new line here.`）。

## 三、应用补丁的方法

- 使用 **`patch`命令**：
```bash
patch -p1 < file.patch
```
- `-p1`表示剥离路径的第一级目录（例如去掉 `a/`和 `b/`）。
- **Git** 中可以直接应用：
```bash
git apply file.patch
```
