Kafka 集群由多个 **Broker**​ 组成；消息按 **Topic**​ 逻辑分类；Topic 拆分为多个 **Partition**​ 存到 Broker 磁盘；每个 Partition 有若干 **Replicas**（一主多从），由 **ZooKeeper**​ 协调 Broker 上下线与 Leader 选举，实现分布式高吞吐、不丢消息。
# Broker（Kafka 服务器节点）

它负责**存储数据**、处理 Producer（生产者）发来的消息和 Consumer（消费者）的拉取请求。Broker 启动时会把自己（IP/端口）注册为 ZooKeeper 的**临时节点**。ZK 维护 Broker 列表，谁挂了 ZK 通知集群做重平衡。Kafka 集群就是多个 Broker 组成的，可横向扩容（加机器 = 加 Broker）。

# Topic（主题 / 消息类别）

它是消息的**逻辑分类**（类似数据库里的“表”，或文件夹）。Producer 把某一类业务消息发到指定 Topic，Consumer 订阅 Topic 拿数据。

# Partition（分区，核心存储单元）

它是Topic 的**物理分片**。一个 Topic 可以分成多个 Partition。它是真正存储消息的地方（Append Only 日志文件，存在 Broker 磁盘）。不同 Partition 可分布在不同 Broker 上，Producer/Consumer 可多线程并行读写。
**关键特性**：
- **有序性只保证分区内**：同 Partition 消息先发先存；跨 Partition 不保序。
- **副本机制**：每个 Partition可有多个副本（Leader 在某一 Broker，Follower 同步数据），Leader 挂了（ZK 参与选举）选新 Leader，防数据丢失。
