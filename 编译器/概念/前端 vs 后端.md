# 编译器前端 vs 后端

编译器按"语言相关 / 目标相关"切成两半，中间用 **IR（中间表示）** 隔开——这是理解 LLVM 架构的核心。

```
源码 ──[前端 Frontend]──> IR ──[中端优化]──> IR' ──[后端 Backend]──> 机器码
  语言相关、目标无关        机器无关            目标相关、语言无关
```

## 前端（Frontend）：把"语言"吃掉

| 阶段 | 干什么 |
|---|---|
| 词法分析（Lexer） | 字符流 → token（`int`、`x`、`=`、`42`） |
| 语法分析（Parser） | token → AST（语法树） |
| 语义分析（Semantic） | 类型检查、作用域、名字解析（`x + "abc"` 在这里报错） |

- **一个语言一个前端**：C、C++、Rust、Java、Go 各有各的
- 产出物是 IR（LLVM IR / GCC 的 GIMPLE / JVM 字节码）
- **和目标机器完全无关**——编 x86 还是 RISC-V，前端干的活一模一样
- 报的错：语法错误、类型错误、未定义符号
- 例子：clang（C/C++/ObjC 前端）、rustc 前端、javac、GCC 的 cc1

## 后端（Backend）：把"机器"吃掉

| 阶段 | 干什么 |
|---|---|
| 指令选择 | IR 指令 → 目标指令（`x*3` → `lea`） |
| 指令调度 | 重排指令隐藏流水线延迟（见 [[调度模型]]） |
| 寄存器分配 | 无限虚拟寄存器 → 真实寄存器（图着色） |
| 代码发射 | 生成汇编/机器码、处理 ABI、栈帧 |

- **一个架构一个后端**：x86、ARM、RISC-V、WASM 各有各的
- 关心：指令集、寄存器文件、调用约定、端序、文件格式——也就是 [[编译目标]] 里说的那套
- 报的错：极少（目标不支持某特性时）
- 例子：LLVM 的 X86/AArch64/RISCV Target、GCC 的 RTL 后端

## 中端（Optimizer）：夹在两者之间的大锅

图上的"中端优化"严格说既不属于前端也不属于后端：

- 在 IR 上做**机器无关优化**（CSE、LICM、内联、向量化……，见 [[PGO]]、[[LTO]]）
- 语言无关、目标无关：新语言、新架构都免费复用这一套 pass
- LLVM 里是 `opt`（pass 管道）；GCC 里是 GIMPLE 优化阶段
- 边界会模糊：PGO 影响布局决策、LTO 在链接期跑，都是中端思想向后端/链接期的延伸

## 中间的 IR：为什么它如此关键

没有 IR 的世界：**N 种语言 × M 种架构 = N×M 个编译器**（每个组合写一套）。

```
传统:  C→x86 | C→ARM | C++→x86 | C++→ARM | Rust→x86 ... （9 个组件）
LLVM:  C 前端 | C++ 前端 | Rust 前端  +  x86 后端 | ARM 后端 | RISC-V 后端   （6 个组件）
```

所以：

- 新增一种语言（如 Rust）：只写前端，复用所有后端 → **"一次编写，到处生成"**
- 新增一个架构（如 RISC-V）：只写后端，所有语言立刻支持
- 中端优化（PGO、LTO、传统优化）在 IR 上做一次，所有语言和架构共享

## 几条有用的直觉

- **前端决定"能编什么"**（语言能力、报错质量），**后端决定"编得多好"**（机器码质量、性能）
- clang 的 `--target=` 就是在**同一个前端后换后端**（`x86_64-linux` ↔ `aarch64-linux` ↔ `wasm32`），前端处理完全一样
- rustc = Rust 前端 + **LLVM 后端**（所以 rustc 能编到 LLVM 支持的所有架构，靠 `rustup target add`）
- "编译器"这个词日常常指前端+后端整条链；说"clang 是编译器"时，其实它前端是 clang，后端是 LLVM

## 一句话总结

前端把"语言"变成 IR，后端把 IR 变成"机器"；IR 是两者的合同，也是 LLVM 能用少量组件覆盖 N×M 组合的全部秘密。
