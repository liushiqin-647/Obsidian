> [!info] 核心一句话
> **编译期** = 程序运行**之前**，编译器一次性完成的分析与翻译；
> **运行时** = 程序运行**之中**，支撑程序执行的环境与机制。

## 时间线总览

```
源代码 --(编译期)--> 目标代码/字节码 --(运行期)--> 程序执行结果
        ↑                                    ↑
    编译器负责                             运行时负责
```

## 编译期 vs 运行期

| 维度 | 编译期（编译器做的事） | 运行期（运行时做的事） |
|---|---|---|
| 发生时机 | 程序**运行之前**，一次性 | 程序**运行之中**，持续存在 |
| 做什么 | 词法/语法分析、类型检查、优化、代码生成 | 加载代码、分配内存、执行指令、管理资源 |
| 错误类型 | 编译错误（语法错、类型错），**编译失败就发不了版** | 运行时错误（空指针、越界、除零），运行到那一步才暴露 |
| 谁参与 | 编译器进程，干完就退出 | 运行时环境，与程序同生共死 |

> [!example] 典型例子
> - `String s = 1;` → **编译期**错误（类型不匹配）
> - `s.length()` 遇到 null → **运行期**错误（`NullPointerException`）

## 编译器 vs 运行时（组件层面）

### 编译器（Compiler）

- 一个**构建期工具**，把源码翻译成另一种形式（机器码、字节码、中间表示）
- 静态工作：语法分析、语义检查、优化、代码生成
- 用完即走，不驻留
- 例子：GCC、Clang、`javac`、`tsc`

### 运行时（Runtime）

- 程序**加载和执行时**的支撑环境，通常以库或虚拟机形式存在
- 动态工作：加载器、内存管理/垃圾回收、动态类型检查、异常处理、JIT 编译、标准库实现
- 程序活着它就活着
- 例子：JVM、.NET CLR、V8、Go runtime（goroutine 调度、GC）、C 的 libc/CRT

> [!tip] 直觉比喻
> **编译器是"翻译官"**：把书翻成英文后就不管了；
> **运行时是"剧场"**：剧本在台上演的时候，灯光、音响、换场、救场全是它负责。

### 不同语言运行时轻重差异

| 语言 | 运行时特点 |
|---|---|
| C/C++ | 极薄（CRT 启动代码 + libc），性能可感知 |
| Java / C# / Go | 很重（GC、JIT、反射、调度器），程序依赖它才能跑 |
| Rust | 很小，无 GC，但 panic 栈回溯等仍需少量运行时支撑 |

这也解释了为什么 C 程序能编译成静态二进制到处跑，而 Java 必须装 JVM。

## 补充：编译器的编译器（compiler-compiler / 元编译器）

指**用来"生成编译器"的工具**，与运行时完全是两个维度——它出现在**更早一层**的构建流程里。

- 输入：文法规则（如 EBNF 语法描述）
- 输出：一个**语法分析器**（编译器的一个部件）
- 例子：YACC/Bison、ANTLR、lex/flex

```
文法描述 --(YACC/Bison)--> 语法分析器 --(加入其他部件)--> 完整的编译器 --(编译源码)--> 可执行程序 --(运行时)--> 结果
```

相关概念还有 **自举（bootstrapping）**：GCC 的第一版用别的编译器编译，之后用自己编译自己——这就是"编译器编译编译器"的另一个常见理解。

## 一句话总结

- **编译器**：写代码之后、跑代码之前，一次性把代码"翻译"好
- **运行时**：跑代码的那一刻起，负责"让代码真正跑起来"的一切环境
- **编译器的编译器**：生成"翻译官"的工具，在更上游

## 编译期 vs 运行期：语言的光谱

不同语言把"能做的事"分配在编译期/运行期的比例完全不同：

| 语言 | 编译期承担 | 运行期承担 |
|---|---|---|
| C/C++ | 几乎所有决策（类型、布局、优化、模板展开） | 极少（无反射、无 GC） |
| Java / C# | 类型检查、字节码生成 | JIT 编译、GC、反射、动态代理 |
| Go | 类型检查、编译优化 | GC、goroutine 调度、部分反射 |
| Python / JS | 语法解析（类型基本不查） | 几乎所有事（动态类型、monkey-patch） |

由此推出几条结论：

- C++ 的模板、`constexpr` 把计算塞进编译期 → **运行时零开销**
- Java 的反射、C# 的 `dynamic`、Python 的 monkey-patch 必须靠运行时 → 灵活但更慢、错误暴露更晚
- **JIT 模糊了界限**：V8、JVM 在运行时里又内嵌了一个编译器（把热代码现场编译成机器码）
