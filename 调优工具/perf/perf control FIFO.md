> [!abstract] 一句话
> perf 默认一启动就一直在采；control FIFO 让它先停着，等你往管道里写 `enable` 才开始记录，写 `disable` 就暂停。

## 0. 它是什么

perf control FIFO 是一套控制机制：通过一个命名管道（FIFO）向正在运行的 perf 进程发命令，动态开关采集，不用停掉或重启 perf。

它要解决的问题很具体：一段程序里往往只有中间那截值得测，前面的初始化和后面的收尾都会稀释结果。默认的 perf 从启动采到退出，这些噪音和数据一起进了文件。

## 1. 工作原理

整个过程分三步：

1. **准备一个 FIFO**。用 `mkfifo` 建一个命名管道，控制端和 perf 都通过这个文件说话。
2. **启动 perf 并让它等指令**。`--control fifo:路径` 指定管道，`-D -1` 让 perf 启动后处于“事件禁用”状态，不会抢跑。
3. **写命令**。往管道里写文本命令，perf 读一行执行一行。

```bash
mkfifo /tmp/perf.fifo

perf record -e cycles --control fifo:/tmp/perf.fifo -D -1 ./app

# 在另一个终端或脚本里
echo enable  > /tmp/perf.fifo
echo disable > /tmp/perf.fifo
```

| 命令 | 作用 |
|---|---|
| `enable` | 开始（恢复）记录 |
| `disable` | 暂停记录，已经采到的数据保留 |

## 2. 典型用法

- **手动圈定范围**：程序跑到目标函数之前写 `enable`，函数结束后写 `disable`，采到的就只有这一段。
- **自动化集成**：框架代码在特定事件发生时自己往里写，比如第 N 个事件开始、结束后停止。CERN 的 LHCb 实验软件就是这么做的。
- **跳过预热**：等程序进入稳定状态再打开，避免把启动阶段的抖动算进结果。

和 `--delay` 相比，FIFO 能反复开关，不受“只能定一个时间点”的限制。

## 3. 补充：fd 方式

除了 `fifo:`，`--control` 也接受 `fd:` 形式，直接指定一个已经打开的文件描述符，适合控制端先把管道 fd 准备好的场合。

FIFO 方式的好处是解耦：控制端和被控的 perf 是两个独立进程，只要双方都能访问同一个文件，脚本可以协调，容器内外也能配合。
