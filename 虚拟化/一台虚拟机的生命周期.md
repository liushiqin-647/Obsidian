# 一台虚拟机的生命周期

> [!abstract] 一句话
> 从创建到销毁一共七步，没有一步引入新机制，只是把 CPU、内存、设备、中断按时间顺序摆一遍。

## 0. 七步一张表

| 阶段 | 谁在做 | 本质 |
|---|---|---|
| 创建 | QEMU | 把对象造出来，登记给 KVM |
| 开机 | guest 里的固件 | 从复位向量开始，自己引导系统 |
| 运行 | KVM 与 QEMU | vCPU 线程循环，Exit 了就处理 |
| 暂停 | QEMU | 让 vCPU 线程停手 |
| 快照 | QEMU | 把内存、设备状态、磁盘各存一份 |
| 迁移 | 源端与目的端的 QEMU | 内存分轮搬，最后停一下 |
| 销毁 | QEMU | 释放对象，关闭 fd |

## 1. 创建：先把东西造出来

QEMU 打开 `/dev/kvm`，然后把几样东西依次建出来：申请一块内存当 guest 的内存条，建设备模型，再建虚拟机、登记内存、建 vCPU，最后映射 `kvm_run`。

这一步结束时，KVM 那边有一台空虚拟机，QEMU 这边有一块内存和一堆设备模型，但还没有执行过一条 guest 指令。发了哪些 ioctl，见 [[KVM 的接口层]]。

## 2. 开机：guest 自己跑起来

CPU 复位后会从固定地址取第一条指令，那里放着 QEMU 提供的一段固件，SeaBIOS 或 OVMF。固件枚举设备、读 ACPI 表、找到启动盘，把引导程序读进内存，再交给内核。guest 内核接管页表和中断控制器，最后启动 init。

整个过程里 KVM 只做一件事：让 vCPU 真的执行。引导逻辑全在 guest 里，和真机开机没有本质区别。

## 3. 运行：线程循环

每个 vCPU 线程调一次 `KVM_RUN` 进入 guest，碰到约定的事件退出来，QEMU 处理完再进去。设备访问、中断、EPT 缺页都发生在这个循环里，见 [[vCPU 与线程]]。

## 4. 暂停：让时间停下

暂停就是让 vCPU 线程不再调 `KVM_RUN`。内存和设备状态原地不动，所以恢复只是再调一次。

## 5. 快照：把现在存下来

快照要存三样：guest 内存、设备状态（队列位置和缓存里的数据）、磁盘。停机快照简单；不停机快照要先让 guest 停一下，保证三样东西对齐。

## 6. 迁移：内存分轮搬

目的端按同样的配置先建好一台空虚拟机，内存从源端一轮轮搬过去。先整体拷一遍，之后只拷变化的页，差距越缩越小；小到一定程度就暂停源端，搬完最后一点，在目的端恢复。

停机时间就是最后那一小段，通常几十到几百毫秒。磁盘要么放在共享存储上，要么单独迁一次。

## 7. 销毁：反过来拆

停线程、释放内存、关闭 fd。KVM 侧的对象随 fd 关闭一起释放。

## 8. 谁在编排

QEMU 只管一台。上面通常还有 libvirt 这一层，再上面是云平台，负责选机器、发命令、收集状态。它们不直接碰 KVM 的 ioctl，而是通过 QEMU 的 monitor 接口下命令。
