> [!abstract] 一句话
> 虚拟化没有真的造出一台计算机，它只是把 CPU、内存、设备和中断分别借给 guest，每样配一套骗法，再让它们看起来属于同一台机器。

## 0. 一台虚拟机由什么组成

一台真机要跑起来，得有 CPU 执行指令、内存放代码和数据、设备读写外部世界、中断把外部事件送进来，还得有固件把系统引导起来。虚拟机的做法是逐项对应：

| 真机上的东西 | 虚拟机里对应什么 | 谁提供 |
|---|---|---|
| CPU | vCPU，宿主上的一个线程 | KVM |
| 内存 | 一段宿主内存，加两层地址翻译 | KVM 与 QEMU |
| 设备 | 设备模型加 guest 里的驱动 | QEMU |
| 中断 | 虚拟 LAPIC 加一条注入路径 | KVM |
| 固件与引导 | 一段固件映像和几张 ACPI 表 | QEMU |

前四样各有一套机制，下面按这四样讲一遍；第五样是时间顺序，单独成篇。

## 1. CPU：借出去，还要能收回来

guest 内核也是 ring0，不能降权，所以硬件在 ring 之外又分了一层世界：宿主在 root，guest 在 non-root。两边状态存在 VMCS 里，切进去叫 VM Entry，退出来叫 VM Exit。

关键在于 guest 全速跑，只有提前约定的事才停下来报告，所以计算性能和真机接近。机制细节见 [[CPU 工作模式]]。

## 2. 内存：给它一个假地址空间

guest 的页表翻出来的是 GPA，不是真地址；硬件再用第二层页表把 GPA 翻成 HPA，这一层由 KVM 维护。guest 随便怎么写页表，都翻不出分配给它的那几页。

没映射的 GPA 会触发一次 Exit，KVM 通常在内核里补上映射，不惊动 QEMU。见 [[CPU 工作模式]] 的 §4。

## 3. 设备：三条路线

设备要做的事，是让 guest 以为自己正在跟硬件打交道。做法有三条：

| 路线 | 一次访问由谁处理 | Exit 频率 | 代价 |
|---|---|---|---|
| 全模拟 | QEMU 逐个寄存器模拟 | 每次访问都要出 | 最慢，兼容性最好 |
| virtio | guest 驱动加后端配合 | 一次 I/O 一次 | 要装驱动，快得多 |
| 直通 | 真设备直接交给 guest | 几乎没有 | 要 IOMMU，设备无法共用 |

今天默认走 virtio。一次请求怎么走完，见 [[virtio-blk 前后端]]。

## 4. 中断：设备反过来找 CPU

设备干完活得通知 guest，时钟要打断 guest，vCPU 之间也要互发中断。发起方各不相同，但落到 KVM 上只有两条路。

- **绕用户态**：设备在宿主上产生中断，QEMU 收到之后决定投给哪颗 vCPU，再通过 ioctl 告诉 KVM 注入。老式设备、以及中断控制器需要软件模拟的场合走这条；它最通用，代价是每次投递都要绕一趟用户态。
- **不绕用户态**：这次投递被直接写进内存里的一块记录，KVM 或硬件在 vCPU 下次进 guest 时取走。MSI、irqfd、APICv、posted interrupt 都属于这条，vhost 也靠它把注入留在宿主内核里。

什么情况下只能绕用户态？后端不在宿主内核里的时候，比如 vhost-user 跑在另一个进程；或者 guest 用的中断控制器需要软件模拟，比如 8259 和 IOAPIC 的老路径。

## 5. 生命周期：从生到死

创建、开机、运行、暂停、快照、迁移、销毁。这七步没有新机制，只是把上面四样按时间顺序摆一遍，见 [[一台虚拟机的生命周期]]。

## 6. QEMU 进程里有什么

```
QEMU 进程（用户态）
  ├─ vCPU 线程  ── ioctl(KVM_RUN) ──→  KVM  ──→  物理 CPU
  ├─ guest 内存 ── mmap，与 KVM 共用同一批页
  └─ 设备模型   ── eventfd ─────────→  KVM
```

CPU 那条路要经过 KVM 才能上硬件，内存是两边共用同一批页，设备靠 eventfd 把通知直接送进内核。这三条通道合起来，就是一台虚拟机在宿主上的全部形态。

## 7. 一条主线

所有优化都指向同一件事：少 Exit，或者让每次 Exit 更短。virtio 减次数，ioeventfd 和 vhost 减等待，APICv 让中断不必绕用户态，EPT 补页留在内核里。判断一个特性值不值，先看它站在哪一边。
