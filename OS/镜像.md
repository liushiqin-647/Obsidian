# 镜像（image）

> [!info] 一句话
> 镜像是**把一整个东西的完整内容按原样打包成的文件**：还原出来与原件一模一样，所以叫“镜像”。
> 它复制的是**布局**（分区表、文件系统元数据、引导扇区），不是零散文件。

## 1. 三种常见镜像

| 类型 | 里面是什么 | 例子 |
|---|---|---|
| **磁盘镜像** | 一块磁盘的原始字节：分区表、文件系统、引导扇区、空闲块 | `dd` 出的 `disk.img`、`qcow2` |
| **容器镜像** | 目录树 + 元数据（启动命令、环境变量），**没有磁盘概念** | Docker / OCI image |
| **安装镜像** | 一张光盘的文件系统 | `.iso` |

`qcow2` 是磁盘镜像的一种**格式**：稀疏存储、压缩、快照、backing file，但描述的仍是“一块盘”。

## 2. 镜像 ≠ 普通拷贝

```
cp -r /mnt/rootfs ./backup     → 只有文件，没有分区表、引导扇区、文件系统元数据
dd if=/dev/vda of=rootfs.img    → 连空闲块、inode 位置都保留，可直接启动
```

差别就在“**能不能原样还原成一个可启动的系统**”。这也解释了为什么 `rootfs.img` 能直接挂载或喂给 VM，而一堆文件不行。

## 3. 在链路里的位置

```
镜像文件（存放在某个文件系统上）
   → 作为虚拟磁盘 /dev/vda 出现
   → 盘上有分区与 ext4
   → 挂载到 / 才成为 rootfs
```

所以镜像**不是**“装 rootfs 的盒子”，而是“那块盘的字节快照”。rootfs 是它接上并挂载之后的身份，见 [[rootfs]]。

容器没有这一层：

```
容器镜像（层 + 元数据）→ 解开成目录树 → pivot_root → 容器的 /
```

## 4. 镜像 vs 快照 vs 内存备份

| 名字 | 包含什么 | 恢复后 |
|---|---|---|
| 磁盘镜像 | 磁盘字节（分区、文件系统） | 一块盘，进程要重新启动 |
| 容器镜像 | 文件系统 + 启动配置 | 起一个新容器，无旧进程 |
| **VM 快照** | 磁盘 + **内存** + 设备状态 | 进程原样继续跑 |
| 休眠镜像 | 内存写入交换区 | 唤醒原系统 |
| core dump | 进程内存 | 只能调试，不能运行 |

- **镜像**回答“系统长什么样”（有哪些文件、什么版本）；
- **快照**回答“系统此刻处于什么状态”（寄存器、堆栈、打开的文件、连接）。

> [!note] “镜像包括内存吗”
> 默认**不包括**。需要内存的是快照类的东西：QEMU 的快照是“磁盘增量 + 内存文件 + 设备状态”三件套；Firecracker 的 memory file 与 rootfs 镜像也是分开存放的。

## 5. 为什么叫“镜像”

因为还原后与原件**完全一致**——像照镜子。不是“把数据镜像到另一块盘”那个动词义，而是“一份等价的副本”。

## 6. 常见误解

- **镜像 = 压缩包？** 不一定。raw 镜像完全不压缩，体积等于磁盘大小。
- **镜像 = 备份？** 备份可以用镜像实现，但镜像是产物形态，不是备份策略本身。
- **镜像里有内存？** 没有，除非它明确叫快照或 hibernation image。
- **镜像自己住在哪？** 总得存在某个文件系统上（宿主机的 `/var/lib/...`），这是另一层嵌套。
